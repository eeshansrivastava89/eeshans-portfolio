Generated by the `improve-animations` audit at commit `72a5c80`. Each plan is self-contained — an executor needs no other context.

## Recommended execution order

1. **001** — highest leverage; the modal is the biggest interactive moment on the site.
2. **003** — quick, tactile, touches every page.
3. **002** — small, self-contained React island.
4. **004** — one file, isolated.

## Dependencies & conflicts

- **001 and 003 both touch `src/layouts/Base.astro`** (001 edits the `<dialog>` class + adds CSS; 003 edits the `.modal-close` button class). Different regions, but if executed by agents in parallel worktrees they will conflict on merge. Run them **sequentially** (001 first), or hand both to one executor.
- 002 and 004 are fully independent of each other and of the Base.astro plans.
- None of these plans introduce motion tokens. If a future "shared easing tokens" plan runs, it should consolidate the literal `cubic-bezier(0.23, 1, 0.32, 1)` values these plans add.

## Executing

Any agent (or a cheaper model) can execute a plan — the plan contains exact current code, exact target code, steps, boundaries, and verification. In this harness:

```
improve-animations execute plans/001-animate-demo-modal.md
```

or simply hand the plan file to any coding agent. After execution, re-review the diff at the `review-animations` bar.
